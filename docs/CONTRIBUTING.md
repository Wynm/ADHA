# المساهمة في ADHA

شكراً لأنك هنا. المشروع مبني على قاعدة واحدة: **كل ادّعاء يجب أن يكون قابلاً للفحص**.

## قبل أن تبدأ

```bash
npm install
npm run dev      # التطوير
npm run verify   # lint + 79 اختباراً + build — يجب أن ينجح قبل أي PR
```

## أين تضيف؟

| ما تريد إضافته | المكان |
| --- | --- |
| مسار ربح جديد | `src/data/opportunities.js` |
| قاعدة كشف احتيال | `src/lib/scamRules.js` (+ اختبار في `tests/scam.test.js`) |
| سؤال في المراجعة أو البوصلة | `src/components/Review.jsx` / `Compass.jsx` |
| أسبوع في مسار التعلّم | `src/data/curriculum.js` |
| حالة واقعية | `src/data/cases.js` |
| مصطلح في المعجم | `src/data/lexicon.js` |
| قسم جديد كامل | `src/components/` + إضافته إلى `App.jsx` و`journey.js` |

> قسم جديد **لن يُقبل** إن لم يُضف إلى `src/data/journey.js` — يوجد اختبار يتحقق أن كل قسم في التطبيق مُفهرس، وأن كل رابط في الفهرس يشير إلى قسم حقيقي.

## قواعد صارمة (ليست تفضيلات)

1. **لا وعود دخل.** لا «اربح 1000$»، لا «مضمون»، لا شهادات غير قابلة للتحقق. أي نص من هذا النوع يُرفض.
2. **كل رقم له معادلة.** إن أضفت رقماً في واجهة، يجب أن تكون معادلته في `src/lib/` وقابلة للاختبار.
3. **لا خوادم، لا تتبّع.** لا `fetch` خارجي، لا تحليلات، لا كوكيز. البيانات في `localStorage` فقط.
4. **RTL أولاً.** كل واجهة جديدة تُختبر بعرض 360px وبالعربية أولاً، ثم بالإنجليزية.
5. **الحدود تُكتب، لا تُخفى.** إن كان للنموذج افتراض مثالي، اكتبه في الواجهة وفي `docs/METHODOLOGY.md`.

## أسلوب الكود

- React 19، مكوّنات دالّية، hooks فقط.
- المنطق الخالص في `src/lib/` (بلا JSX) ليكون قابلاً للاختبار بلا متصفح.
- Tailwind للأسلوب؛ تجنّب قيم opacity غير القياسية (`border-white/8` ❌ → `border-white/[0.08]` ✅).
- الحركة: أي `motion` يجب أن تحترم `prefers-reduced-motion` (الملف العام يغطي معظم الحالات).
- نصوص عربية فصيحة، بلا مبالغة، وبلا علامات تعجّب متعددة.

## اختبارات

```bash

npx vitest run tests/scam.test.js   # ملف واحد
```

اختبار جيد هنا يجيب: «ما الادّعاء الذي قد ينكسر لاحقاً؟» — لا «كم سطراً تُغطي؟».

## Pull Request

- عنوان واضح + وصف يقول **ماذا ولماذا**، لا «تحسينات».
- PR واحد = تغيير واحد متماسك. لا تخلط محتوى مع إعادة هيكلة.
- إن أضفت محتوى تعليمياً، اذكر مصدر الفكرة أو الحالة الواقعية (بلا أسماء أشخاص).

## ما لا نقبله

- «حيلة» أو «اختراق» لتجاوز قواعد منصة.
- محتوى يُشجّع على التداول عالي المخاطر كدخل أول.
- أنظمة إحالة أو تسويق شبكي بأي صياغة.
- جمع بيانات المستخدمين، حتى «لتحسين التجربة».
